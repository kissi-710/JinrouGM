# 02 Discord 側の仕様(GM Bot)

## 1. 前提
- 1 つの Discord サーバー(guild)で、同時に進行できる試合は **1 つ**。
- 1 人(または 1 Bot)が同時に参加できる試合は 1 つ。
- **同じ持ち主の席(本人+その人の Bot)は、1 試合に 1 つまで**。持ち主は自分の Bot の個人部屋を見られるため、複数席を持つと秘匿情報が混ざる。〔仮決定 U-23〕

## 2. チャンネル

### 2.1 一覧
| チャンネル | 作成 | 閲覧 | 発言 | 用途 |
|---|---|---|---|---|
| `#lobby` | `/setup` で常設 | 全員 | 全員 | 登録・参加・設定・リザルト |
| `#village` | `/setup` で常設 | 全員(試合中の非参加者は観戦者ロールのみ) | 試合中の生存者 | 昼の議論・CO 一覧 |
| `#log` | `/setup` で常設 | 全員 | GM のみ | 公式告知 |
| `#wolves` | `/setup` で常設 | GM と生存中の人狼(死亡した人狼は閲覧のみ) | GM と生存中の人狼 | 人狼の相談・襲撃 |
| `#graveyard` | `/setup` で常設 | 死者・観戦者 | 死者・観戦者 | 死者の雑談 |
| `#debug` | `/setup` で常設 | GM と運営者 | GM のみ | 運用ログ |
| `#priv-<player>` | 登録時に 1 回 | GM と本人(Bot の場合は Bot と持ち主) | GM と本人(持ち主は閲覧のみ) | 個人の秘匿情報・行動入力 |

- 共有チャンネルは試合ごとに作り直さず、`/setup` で 1 回だけ作り、試合開始・死亡・終了時に permission overwrite を更新する。設計書 §3.2 の「試合開始時に作成」は、個人部屋を常設にした方針に合わせて常設に変えた。〔仮決定 U-24〕
- 観戦者は `#village` `#log` に加えて `#graveyard` も閲覧・発言できる。設計書 §3.2 の表(死者+観戦者)と本文(`#village` `#log` のみ)が食い違っていたため、表に合わせた。〔仮決定 U-25〕
- 試合のプレイヤーは、試合中は観戦者になれない。死亡したプレイヤーは `#graveyard` に入る。

### 2.2 個人部屋
- 名前は `priv-<表示名を小文字化・記号除去>`。重複したら末尾に連番。役職名は入れない。
- カテゴリ `PRIV-1`, `PRIV-2`, … に 50 個ずつ入れる(カテゴリの上限)。
- 退会(`/unregister`)時はアーカイブ(閲覧権を外して `ARCHIVE` カテゴリへ移す)。〔仮決定 U-26〕
- GM の投稿には必ず `game_id` を含める。

### 2.3 権限の更新タイミング
| タイミング | 更新内容 |
|---|---|
| `/start` | `#village` に参加者の発言権を付与、非参加者の発言権を外す。`#wolves` に人狼のみ閲覧・発言を付与。 |
| 死亡時 | `#village` の発言権を外す。`#graveyard` に追加。人狼なら `#wolves` を閲覧のみに。 |
| GAME_OVER | `#village` を全員閲覧のみに戻す。`#wolves` `#graveyard` を全員閲覧可(過去ログ公開)。 |
| 次の `/start` | `#wolves` `#graveyard` の閲覧を再び制限する。過去試合のメッセージは残る(正式な記録は DB)。〔仮決定 U-27〕 |

### 2.4 起動時の突合
GM は起動時に `guild_config` のチャンネル ID と実在するチャンネル・権限を突き合わせ、差分を `#debug` に出す。進行中の試合があればイベントログから状態を復元し、権限を状態に合わせ直す。

## 3. コマンド

### 3.1 入力方法
- **人間**:スラッシュコマンド(`/vote 4`)。応答はエフェメラル。本人は Interaction の `user.id` で特定する。
- **AI(Bot)**:メッセージ本文の先頭が `!` の構造化テキスト(`!vote 4`)。本人は `message.author.id` で特定し、登録済み Bot ID と照合する。
- 両者は同じコマンド定義を共有し、Engine には同じ入力として渡す。
- AI のコマンド書式:`!<command> <arg1> <arg2> ...`。区切りは半角/全角スペース。全角数字・全角 `!`(`!`)は半角に正規化する。〔仮決定 U-28〕1 メッセージ 1 コマンド。

### 3.2 一覧

**運営・ロビー系**(`#lobby` で有効。`/setup` `/admin` はどこでも可)

| コマンド | 実行できる人 | 内容 |
|---|---|---|
| `/setup` | サーバーオーナー | 常設チャンネルと `guild_config` を作る。再実行は不足分の補修のみ |
| `/admin add|remove @user` | サーバーオーナー | 運営者の登録・削除〔仮決定 U-29〕 |
| `/register` | 人間本人 | 自分を登録し、個人部屋を作る(登録済みなら再利用) |
| `/register bot:@Bot owner:@User` | 運営者 | Bot を許可リストに登録し、個人部屋を作る |
| `/unregister [bot:@Bot]` | 本人・持ち主・運営者 | 登録解除。個人部屋はアーカイブ |
| `/session profile:<文字列>` / `!session <文字列>` | 登録済みの人(AI は Bot 自身) | 試合を作る(LOBBY)。進行中の試合があれば拒否 |
| `/join [bot:@Bot]` | 本人。Bot は持ち主または運営者 | LOBBY の試合に参加 |
| `/leave [bot:@Bot]` | 同上 | LOBBY 中のみ参加取消〔仮決定 U-30〕 |
| `/start` | 権限者 | プロファイルを確定し、配役して開始 |
| `/spectate` / `/unspectate` | 試合に参加していない人 | 観戦者ロールの付与・解除 |
| `/status` | 誰でも | 公開情報(フェーズ・日数・締切・生存者・構成)を表示〔仮決定 U-31〕 |
| `/abort` | 権限者 | 試合中止(LOBBY 中も可) |
| `/suddendeath <index>` | 権限者 | 突然死 |
| `/export [game_id]` | 誰でも(終了した試合のみ) | JSON/Markdown のログを添付で返す〔仮決定 U-32〕 |

**ゲーム系**

| コマンド | 有効な場所 | 有効なフェーズ | 内容 |
|---|---|---|---|
| `divine <index>` | 自分の `#priv` | NIGHT(占い師) | 占い |
| `guard <index>` | 自分の `#priv` | NIGHT(騎士) | 護衛 |
| `attack <index>` | 自分の `#priv` / `#wolves` | NIGHT(人狼) | 襲撃 |
| `suspect <index>` | 自分の `#priv` | NIGHT(行動のない役職) | ダミー入力 |
| `vote <index>` | 自分の `#priv` | DAY_VOTE / RUNOFF | 投票 |
| `co <role> [i=white\|black ...]` / `co cancel` | `#village` | DAY_DISCUSS | CO |
| `pass` | `#village` / 自分の `#priv` | DAY_DISCUSS(発言終了)、NIGHT(行動なし) | 発言終了・行動なし |

- 秘匿系(`divine` `guard` `attack` `suspect`)を他の場所で打ったら拒否する。`#village` で打たれた AI のメッセージは、拒否に加えて GM が削除する(秘匿情報の漏れを抑える)。〔仮決定 U-33〕
- 人間は夜の行動・投票を、個人部屋のボタン/セレクトメニューでも入力できる(M3 以降。スラッシュコマンドと同じ入力になる)。

### 3.3 応答
- 受理:`✅受理 [game_id] <command> <args>`(AI は自分の `#priv` に、人間はエフェメラル)。
- 拒否:`❌拒否 [game_id] <エラーコード>: <理由>`。AI が再試行できるよう、エラーコードは固定文字列にする。

| エラーコード | 意味 |
|---|---|
| `E_FORMAT` | 書式が不正 |
| `E_UNKNOWN_CMD` | 未知のコマンド |
| `E_PHASE` | 今のフェーズでは使えない |
| `E_PLACE` | このチャンネルでは使えない |
| `E_ROLE` | 自分の役職では使えない |
| `E_TARGET` | 対象が不正(範囲外・死者・自分・連続護衛など) |
| `E_DEAD` | 死亡しているため不可 |
| `E_NOT_IN_GAME` | 試合に参加していない |
| `E_PERMISSION` | 権限がない |
| `E_COOLDOWN` | クールダウン中(残り秒数を付ける) |
| `E_TOO_LONG` | 文字数超過(上限を付ける) |
| `E_LIMIT` | 発言回数の上限 |
| `E_PROFILE` | プロファイルが不正(項目と理由を付ける) |
| `E_STATE` | 試合の状態と合わない(進行中の試合がある、人数不足など) |

## 4. GM が送るメッセージ

### 4.1 形式
人間向けの本文と、機械可読な JSON を 1 通に入れる。JSON は末尾に言語名 `gm` のコードブロックで置く。

````text
【2日目 夜】あなたは占い師です。占う相手を選んでください。(締切: 21:03:00 / 180秒)
候補: 0:Alice 1:Bob 3:Dave 4:Eve
返信形式: /divine 3   (AI は !divine 3)
```gm
{"v":1,"game_id":"g20261121-001","type":"prompt","phase":"night","day":2,"action":"divine","options":[0,1,3,4],"deadline":"2026-11-21T12:03:00Z"}
```
````

- 設計書 §3.3 の HTML コメント(`<!-- gm:... -->`)は Discord では隠れず表示されるため、コードブロックに変えた。〔仮決定 U-34〕
- 例の候補番号は 0 始まりの index に揃えた(設計書の例は 1 始まりに見えていた)。
- `deadline` は UTC の ISO 8601。本文の時刻は JST。

### 4.2 `type` の一覧
| type | 送り先 | 内容 |
|---|---|---|
| `role` | `#priv` | 役職通知。`role`、`members`(index と名前の一覧)、人狼なら `wolves`(仲間の index) |
| `prompt` | `#priv` | 行動を求める。`action`(`divine` `guard` `attack` `suspect` `vote`)、`options`、`deadline` |
| `result` | `#priv` | 占い/霊媒の結果。`kind`(`divine`/`medium`)、`target`、`is_wolf` |
| `ack` / `error` | `#priv` | 受理/拒否。`command`、`code` |
| `phase` | `#log` | フェーズ開始。`phase`、`day`、`deadline` |
| `dawn` | `#log` | 犠牲者。`victims`(index の配列。空なら犠牲者なし) |
| `vote_result` | `#log` | 投票結果。`tally`、`votes`(公開時のみ)、`executed`、`runoff` |
| `co_list` | `#village`(固定) | CO 一覧 |
| `game_over` | `#log` `#village` `#lobby` | 勝敗・全員の役職・夜の行動の要約 |
| `admin` | `#log` | 中止・突然死。`by`、`target` |

- 夜のプロンプトは全員に同じタイミング・同じ形式で送る。人狼は `#priv` のプロンプトに加えて `#wolves` にも同じ内容を送る。
- 初夜の前に `role` を送る。

### 4.3 秘匿の守り
- 夜は全員が提出しても締切まで結果を出さない。
- `#debug` に試合中の秘匿情報(役職・夜の行動・投票内容)を出さない。verbose モード(既定オフ)は運営者が明示的に有効にしたときだけ。試合終了後は出してよい。トークンは常に出さない。

## 5. 発言の制御(`#village`)
- GM は受信した時点で、発言をイベントログに保存する(削除する前に保存)。
- クールダウン中・文字数超過・回数超過・死者の発言は受理しない。GM が削除し(GM のみ Manage Messages を持つ)、本人の `#priv` に理由を通知する。主な制御は SDK 側(`speak()` が拒否)で、削除は保険。
- 編集・削除は無視する。編集されたメッセージは別イベントとして記録するが、議論の内容としては元の発言を正とする。
- 議論フェーズ以外の `#village` への発言も削除する(コマンドの応答は除く)。〔仮決定 U-35〕
- GM 自身の投稿は送信キューで整形し、Discord のレート制限(約 5 通/5 秒/チャンネル)に収める。

## 6. 試合の流れ(Discord 上)
1. `/session` → `#lobby` に試合カード(game_id・プロファイル要約・参加者一覧)を出す。
2. `/join` で参加。参加者一覧を更新。
3. `/start` → 確定した設定(役職構成を含む)を `#lobby` に公開。index と役職を割り当て、権限を更新し、`role` を送る。
4. 初夜 → 夜明け → 昼の議論 → 投票 → 処刑 → 夜 … を自動進行。各フェーズ開始を `#log` に告知。
5. 終了 → `game_over` を `#village` `#log` `#lobby` へ。権限を戻し、ログを `#log` に添付する。
